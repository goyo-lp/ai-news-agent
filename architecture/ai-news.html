Migration Plan · deepagents · LangGraph · OpenRouter

News → LinkedIn Deep Agent

A phase-by-phase plan to go from two standalone linear pipelines (the deterministic AI News Agent + the 13-node LinkedIn Agent) to a single coordinator deep agent that consumes curated news as a tool, researches each topic with an isolated adaptive subagent (fetching the real article when it decides to), and writes LinkedIn post proposals in your voice — while reusing the tested code you already have.

~30 PRs · each ≤ 500 LOC Target framework: create_deep_agent() (coordinator-worker) Host repo: AI News Agent (evolves into coordinator)

Every fork below is settled (2026-07-18). The LinkedIn agent's source is now vendored in-repo at reference/linkedin-agent/ for the port, and it already ships on deepagents.create_deep_agent — so the target framework is proven in your own code, not just assumed.

The LinkedIn logic is ported in (Tavily, verifier, technical ranker, style profile, post generation, deep-agent layer), each module vendored alongside the tool/subagent that wraps it.

✓ B — Framework
deepagents create_deep_agent (coordinator + subagents), not a single ReAct agent.
Context isolation, per-subagent model override (keeps the Stage A/B split), reuse of existing logic as tools. Already a dependency and in use inside the LinkedIn agent's investigation node.
✓ C — Delivery
Telegram only — two bots, one process. The news bot keeps the daily digest; a new linkedin bot receives post proposals. Proposals auto-send as drafts once they pass the quality gate — you manually post the good ones to LinkedIn. No LinkedIn API, no review hold.
Quality gate is the only filter; failures are dropped, not retried endlessly.

✓ E — Topic source

✓ F — Migration style
Full rebuild per this plan. Build the coordinator + research/writer subagents fresh, prove parity, cut over, then delete the legacy 13-node graph — not an incremental wrap of the old graph.
✓ G — Cross-run dedup
Reuse the news pipeline's delivery-history.json + novelty. Topics are already deduped upstream; no separate LinkedIn-post history file.
✓ H — Trigger
Manual CLI for now (python -m app.main propose). The news run keeps its existing trigger. Scheduling added later once quality is dialed in.
✓ I — Observability
LangSmith tracing only. The LinkedIn agent's langgraphics (git+https) node-graph visualizer is dropped — the coordinator isn't a fixed LangGraph, so it no longer maps cleanly. Removes a git dependency.

Lean alternative: sonnet-5 for both research and writing.

Two Telegram bots, one process. Delivery is multi-destination and config-routed. The existing News bot keeps receiving the daily news digest through the unchanged run path. A new LinkedIn bot receives every post proposal the deep agent produces, via deliver_telegram(bot="linkedin"). Each bot is a named profile (its own token + chat id) held in one Settings; the existing TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID map to the news profile for backward compatibility, so nothing about today's digest changes.

03Six guiding principles

  1. Deterministic work stays code, exposed as tools. Never agentify a fixed recipe — you'd pay tokens to re-derive tested logic.
  2. Spend agency only where decisions are open-ended. The one genuinely adaptive surface is per-topic research: "fetch the real article or trust the text? verify what? what's technically new?"
  3. Structured data lives in the filesystem/StateBackend; subagents return only compressed findings. A subagent's single text report is lossy — never route the full ranked-article list through it.
  4. Preserve the Stage A / Stage B model split via per-subagent model overrides (cheap ranker, strong researcher/writer).
  5. Reuse, don't rewrite. The news pipeline, SSRF-guarded fetch, Tavily client, Telegram client, and style profile are assets — wrap them.
  6. Every change ships as a ≤500-LOC PR with tests. Dry-run parity against the old pipeline before any cutover.

05The plan, phase by phase

Nine phases, roughly sequential but with parallelizable PRs inside each. The critical path runs Phase 0 → 1 → (2 ∥ 3) → 4 → 5 → 6 → 8; Phase 7 (observability/security) can land alongside 5–6.

PHASE 0Scaffolding & data contracts
Goal: a clean coordinator package and one shared schema module both sides speak, so nothing downstream drifts. Outcome: green CI, empty agent imports, serializable models.
  • Stand up the coordinator package (deps: deepagents, langchain, langgraph, langchain-openai) with ruff/mypy/pytest/CI.
  • Define the boundary types once: CuratedArticle, TopicCandidate, ResearchBrief, PostProposal.
PRs: P0.1, P0.2
PHASE 1News pipeline becomes an in-process tool (the producer)
Goal: the repo's own news pipeline stops "delivering" and starts "returning data," then gets wrapped as a tool that writes into the deep agent's filesystem. Outcome: the coordinator pulls today's curated, ranked, summarized articles by a direct in-process call — no cross-repo packaging.
  • Refactor the pipeline to expose run_curation() → list[Article] (ingest→enrich→rank→summarize, stop before deliver). CLI unchanged.
  • Unify config: one Settings covering OpenRouter + Tavily + Telegram + deep-agent knobs (news + ported LinkedIn settings).
  • Wrap as fetch_curated_ai_news tool that writes /data/articles.json to state and returns only a compressed summary.
PRs: P1.1, P1.2, P1.3
PHASE 2Deterministic logic becomes tools
Goal: extract the LinkedIn agent's tested logic into standalone tools the coordinator and subagents call — so "follow the LinkedIn logic" means literally calling the same functions. Outcome: ranking, article fetch, search, verification, and quality gate all callable in isolation.
  • technical_rank — reuse the technical ranker/scoring; reads articles file → writes ranked topics.
  • fetch_article — the "go get the real article" tool; reuse the News Agent's SSRF-guarded, size-capped fetch + OpenGraph/text extraction.
  • tavily_search / tavily_extract — wrap the existing Tavily client.
  • verify_claim — wrap the brief verifier (model + evidence).
  • quality_gate — word-count 105–182, single-topic, anti-hype checks.
PRs: P2.1 – P2.5
PHASE 3Voice becomes a skill
Goal: encode your writing voice as the one thing that is genuinely instructions. Outcome: a loadable /skills/linkedin-voice/ and a style-profile loader the writer subagent reads.
  • Author SKILL.md: tone, anti-hype rules, structure, word limits, derived from style_samples/.
  • Load data/style_profile.json into agent state (reuse style_profile.py builder).
PRs: P3.1, P3.2
PHASE 4The two subagents
Goal: stand up the isolated adaptive workers. Outcome: a research subagent that turns a topic+URL into a verified brief (deciding for itself whether to fetch the real article), and a writer subagent that turns a brief+voice into a post proposal.
  • research-subagent — tools: fetch_article, tavily_search/extract, verify_claim; model = Stage B; returns a compressed ResearchBrief to /briefs/.
  • writer-subagent — skill: linkedin-voice; reads brief + style profile → PostProposal (must pass quality_gate).
PRs: P4.1, P4.2
PHASE 5The coordinator
Goal: wire everything into create_deep_agent with a StateBackend and an orchestration prompt that plans and delegates. Outcome: an end-to-end dry run that produces N post proposals.
  • Configure StateBackend + file conventions (/data/articles.json, /topics.json, /briefs/, /drafts/).
  • create_deep_agent(tools=[...], subagents=[research, writer], skills=[...], backend, context_schema).
  • Orchestration prompt: plan → fetch → rank → per-topic delegate research → write → quality-gate (retry on fail) → deliver.
PRs: P5.1, P5.2, P5.3
PHASE 6Delivery (two bots) & outputs
Goal: ship LinkedIn proposals to a dedicated LinkedIn bot, keep the news digest flowing to the News bot, and persist artifacts. Outcome: two Telegram bots served from one process; each proposal sent as its own message; per-run outputs on disk.
  • Multi-bot routing: refactor telegram_client to target a named bot profile (token + chat); the news run path uses the news profile, unchanged.
  • deliver_telegram(bot="linkedin") tool — one message per proposal; retry + token redaction preserved; dry-run preview names the target bot.
  • export_report tool → outputs/YYYY-MM-DD/{posts.md, run_report.json, briefs.json}.
PRs: P6.1, P6.2, P6.3
PHASE 7Observability, cost & security
Goal: make runs traceable, costed, bounded, and safe. Outcome: LangSmith traces, an end-of-run cost summary, env-driven model overrides, and an SSRF-hardened fetch tool. Can land alongside Phases 5–6.
  • LangSmith tracing across coordinator, subagents, tools.
  • API usage/cost tracker (reuse api_usage_tracker.py).
  • Per-subagent model config from env (Stage A cheap / Stage B strong).
  • SSRF guard + streaming size cap on fetch_article.
PRs: P7.1 – P7.4
PHASE 8Parity, cutover & cleanup
Goal: prove the deep agent matches or beats the old graph, switch the entrypoint, then delete the dead pipeline. Outcome: run uses the coordinator; the legacy 13-node graph is gone.
  • Full deterministic dry-run E2E snapshot test.
  • Parity harness: the LinkedIn repo's pipeline vs this coordinator on the same date fixtures; document deltas.
  • CLI: new propose subcommand drives the coordinator; the existing news run stays as the digest path.
  • Remove interim port scaffolding + orphaned imports. The news pipeline is retained — it's the producer tool.
PRs: P8.1 – P8.4
