AI News Agent — Architecture

A LangGraph-based AI news digest agent that pulls ~30 AI-news RSS feeds, enriches each article with OpenGraph metadata, filters out previously delivered stories, clusters and ranks by a relevance-first formula (optionally blended with one batched LLM re-rank call), generates exactly 3-sentence LLM summaries via OpenRouter, and delivers one Telegram message per story.

5-node graph + early-exit edge Entry: src/app/main.py Run: PYTHONPATH=src python -m app.main run State: per-run, plus JSON delivery history

01Overview

Cuts through the noise of dozens of AI-news RSS feeds by clustering duplicate coverage, prioritizing high-signal business/product developments over low-signal event roundups, filtering to only today's articles, skipping stories already delivered in previous runs, and producing a clean Telegram digest with AI-written summaries.

07Ranking & Clustering

Deterministic keyword/phrase base score in services/scoring.py, optionally blended with one batched LLM relevance call over the top-40 pool (nodes/rank.py:18-19: 0.7·score + 0.3·llm; skipped on dry-run, missing key, or any failure).

Base score formula

# score_article(article, cluster_size, recent_titles) — scoring.py:387 score = 0.38·relevance + 0.24·recency + 0.14·source_weight + 0.10·duplication + 0.09·cluster + 0.05·novelty
relevance (0.38)
Tokenize title+summary; sum boosts across 6 keyword categories (product launch, tech dev, startup funding, enterprise adoption, deals, frontier companies — OpenAI/Anthropic/Gemini/xAI/Cursor/…). High-phrase hits +0.07 (max 2); low-priority penalty 0.08–0.22. Clamped 0–1.
recency (0.24)
≤6h=1.0 · ≤24h=0.8 · ≤48h=0.6 · ≤96h=0.4 · else=0.2 · None=0.3
source_weight (0.14)
11 hardcoded reputations: OpenAI/DeepMind/Anthropic/Meta = 1.0 → ZDNet = 0.80; default 0.70
duplication (0.10)
Boosted by duplicate_count (same URL across feeds, within one run)
cluster (0.09)
Boosted by cluster_size (same-story grouping across sources)
novelty (0.05)
1 − max title similarity vs stories delivered in the last 14 days (data/delivery-history.json); 1.0 when no history

Same-story clustering — _same_story() scoring.py:340

Similarity = 0.65·Jaccard + 0.35·SequenceMatcher on title tokens.
  • strong: similarity ≥ 0.78 AND token overlap ≥ 0.5
  • moderate: similarity ≥ 0.62 AND overlap ≥ 0.7 AND time-aligned (≤120h apart)
cluster_articles() (scoring.py:363): sort newest-first, greedily assign to first matching cluster. Then one representative (max score) per cluster is selected — duplicate coverage collapses to a single story.

Title: <effective_title> Source: <source_name> Published: <UTC ISO> URL: <url> Context: <effective_summary_source> Write exactly 3 sentences focused on key facts and why this matters.

Robustness

Retry
If response <3 sentences → append "Rewrite your answer as exactly 3 sentences." and call once more (openrouter_client.py:100-108).
Post-process
enforce_sentence_count(text, 3) truncates to exactly 3 or pads with fallback sentences.
Fallback (no LLM)
When dry_run=true or no OPENROUTER_API_KEY → _fallback_summary() deterministic template. API exceptions also fall back here.

Relevance re-rank — score_articles_relevance() openrouter_client.py:133

Call shape
One POST /chat/completions per run: numbered list of ≤40 titles + trimmed context, temperature=0. Asks for a JSON object of 0–100 scores.
Parsing
parse_relevance_scores() (openrouter_client.py:20): extracts the first JSON object, drops unknown/malformed keys, normalizes to 0–1.
Blend
rank_node re-scores candidates as 0.7·base + 0.3·llm, re-sorts, cuts to limit (nodes/rank.py:73-90).
Fail-safe
Dry-run, missing key, HTTP error, or unparseable output → empty result → deterministic order stands. The pipeline never fails because of this call.

11Operations

How to run it, what's automated, and what isn't.

Run commands

# standard run (real Telegram delivery) PYTHONPATH=src python -m app.main run # dry-run (no API calls — preview only) PYTHONPATH=src python -m app.main run --dry-run # limit to N stories (clamped 1–50) PYTHONPATH=src python -m app.main run --limit 10 # verbose logging PYTHONPATH=src python -m app.main run --verbose # console-script alias (if installed) ai-news-agent run

Scheduling / automation

No scheduler for the pipeline. The news agent is manual CLI-triggered only (build_plan/build plan.md:18). The only cron in the repo is .github/workflows/openwiki-update.yml — daily 08:00 UTC — which only refreshes the OpenWiki documentation via openwiki code --update. It does not run the news pipeline. To automate the digest, add your own cron/launchd/GitHub Action calling the run command above.
